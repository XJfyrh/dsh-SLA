# DSH SLA

给项目一句改进目标，SLA 自己调查项目、建立可执行判断依据，并连续尝试改进。你可以随时补充要求、暂停或继续；每次尝试留下检查结果，最后由你选择是否采用。

这是面向 **DeepSeek Harness 0.2.1-rc.2 / Node.js 24** 的最小插件，使用原生会话入口、右侧探索面板和独立实验会话。

## 安装和使用

需要 Node.js 24、Git、DSH 0.2.1-rc.2 和已登录的模型账号。新机器先运行一次 `dsh --profile sla-dev --from-default-profile web` 建立 Web profile，退出后再安装；本机已完成此步骤。

```powershell
npm install --legacy-peer-deps
npm run build:client
dsh plugin --profile sla-dev add E:\dev\dsh-plugins\dsh-SLA
dsh --profile sla-dev --no-open --port 3080
```

打开命令输出的地址，在工作区选择一个项目，新建会话并选择 **持续探索 · SLA**，直接发送目标，例如：

> 让这个项目在大数组上运行得更快，保持现有行为，不增加依赖。

这是插件唯一的模式入口。调查、规划和实验由插件自动调度，无需另外选择执行模式。

0.3 默认附带“代码性能”和“缺陷修复”两个任务扩展。直接描述目标，Agent 会调查项目并选择合适方法；选择理由和扩展版本显示在判断依据中。性能任务显示数值，修复任务显示“缺陷已复现 → 修复通过”。

例如复制 `examples/clamp-bug` 后发送：

> 修复 clamp(0, -5, 5) 错误返回 -5 的问题，保持其他行为，不增加依赖。

随附的 `examples/duplicates-baseline` 是无第三方依赖的初始练习项目，可复制后作为工作区；`examples/duplicates` 保留首版已采用的结果。新版 Web 验收使用独立副本，插件不会要求你事先编写评价脚本。

- **顶部探索入口**：显示当前状态，点击打开右侧探索面板；收起后仍可通过入口重新打开。
- **补充要求**：直接在主对话中补充。保存约束并重建评价依据，旧实验仍可查看；旧版本分数不与新版本混比。
- **暂停 / 继续**：停止当前调用并保留结果；额度用完后，继续会开启新的有限轮次。
- **探索最新状态**：最近一轮已完成的对话下方持续更新探索状态、候选、评价版本和更新时间。暂停、审查与采用后无需翻回最初的启动消息；状态仍通过顶部入口可见。
- **查看依据与实验**：右侧面板先解释改了什么、为什么保留、尚未验证什么，再展开检查与文件改动。新探索的改动说明由执行者撰写，检查名称和保护行为由审查者撰写；检查状态、候选编号、排除结果与版本来自 Host 的实际记录。说明与代码复用 DSH 原生 Markdown、Diff 组件。
- **检查来源**：本次复验与提出检查时的历史发现分开展示，历史记录标注候选和评价版本。旧探索缺少独立摘要或行为名称时明确显示缺失，并保留原文。
- **采用这个结果**：重新检查最佳候选，确认原项目没有变动后写回。原始快照保留；有本地改动时拒绝覆盖。成功后收起当前探索面板，对话中保留结果摘要。

## 运行范围

适合可在本机运行检查的代码项目。调查、规划和执行使用新会话；Host 保存状态、冻结评价文件并独立执行每次检查。默认每轮最多 8 次尝试、20 分钟，每个 Epoch 最多 2 个方向、每方向 2 次局部尝试，每次模型调用最多 24 个工作步、1 个结果提交步，共用 5 分钟上限。提交步不能再读写文件或运行命令；用户暂停和总时限仍立即生效。时间、步骤与轮次上限不是费用硬限。

实验在 `~/.dsh/sla-artifacts/<探索 ID>/` 中，保留初始快照、评价依据、候选、原始检查输出和 `report.json`。重启后暂停，点击继续才恢复。文件快照上限 100 MiB / 15000 文件；跳过 Git 忽略项、依赖/构建目录和 `.env`，遇到符号链接停止。依赖目录不会复制，所以首版优先用于无依赖或依赖已由系统提供的子项目。

自动建立的评价依据应结合任务检查；“通过”表示通过这套检查。当前支持串行多方向 Epoch，保留各方向局部最佳；尚未并行执行 Worker。Windows 文件策略限制写入，不提供进程读隔离或网络隔离。

0.3 会在建立评价和准备采用时独立审查保留行为，新增检查经实际执行后发布为新版评价。右侧面板展示方向、轮次、审查和复验历史。也可以直接说“暂停，把每轮上限改为 12 次、30 分钟，使用 2 个方向”，通过主对话调整设置。

单次工作额度也可在主对话调整，例如“暂停，把每次调用改成最多 48 个工作步、10 分钟”。默认仍为 24 步、5 分钟；每次调用另有 1 个只提交结果的步骤，全部受整轮剩余时间约束。模型的单次输出额度继承 DSH 当前会话配置，插件不另行覆盖。

右侧面板的 **探索设置** 可直接调整本轮尝试数和时间；展开 **高级设置** 可调整单次工作步数、单次时间、方向数与局部尝试次数。运行时先暂停，保存后点击继续；未修改的额度和已用次数、时间保留，方向设置在下一次规划生效。

[核心规则](docs/core.md)说明方向接续、评价升级与恢复。默认任务扩展已从 `1.0.0` 升为 `1.1.0`；旧探索仍可查看，继续或采用需原版本扩展，新规则请新建会话。

## 扩展任务

方法指引使用 DSH Skill，程序能力使用普通 DSH 插件。SLA 提供 `ctx.sla.registerTask()`；扩展声明调查方式、评价和比较规则，核心不要求数值分数或特定执行命令。现有两个任务也走同一个接口。安装、配置和卸载继续使用 DSH。

[扩展开发说明](docs/extensions.md)包含接口、完整实现示例、身份与卸载行为。运行绑定扩展 id/version；缺失或版本变化时停止继续或采用，保留证据。Token 用量仍使用 DSH 原有入口。

## 开发

```powershell
npm test
npm run check
npm run build:client
npm pack --pack-destination artifacts
```

`src/client-factory.js` 是界面源码，`client.js` 是随包交付的浏览器产物。修改 Host 后重启 Harness；修改界面后先构建，再刷新页面。

[设计与官方依据](docs/design.md)记录版本、插件契约和与 SLA 论文的对应范围；[验收记录](docs/validation.md)记录真实 Web 流程、失败修复和复跑方法。原有调研在 `research/`。
