# 0.4 探索内核与默认 SLA 策略

一个目标可以发展多个方向。每个方向保留自己的有效候选，Advisor 根据各方向的实际证据规划下一轮，Worker 每次从本方向的候选继续。所有模型调用仍使用 DSH 新会话；候选、计划与结果由 Host 保存。

本版将持久事实、搜索决策和领域行为分开。内核不规定 Scout/Reviewer 顺序，也不要求制品是文件目录；领域工作流逐步建立判断依据，再使用默认 SLA 策略安排尝试。

| 层次 | 实现与职责 |
| --- | --- |
| 探索内核 | `kernel.js`：尝试、制品血缘、独立观测、保留决定、目标与评价版本；验证身份一致后发布 |
| 默认 SLA 策略 | `sla-strategy.js`：Epoch、局部分支积累、全局选择、不可比候选保留、评价升级后的重排 |
| 生命周期 | `runtime.js`：启动、暂停、继续、额度、调用身份与持久化，不导入领域工作流 |
| 代码工作流 | `code-workflow.js`、`review.js`：项目快照、Scout、保留行为审查、冻结评价与文件写回 |
| 注册工作流 | `native-workflow.js`：为扩展提供状态快照、调用、封存、评价、搜索与交付命令 |
| 应用组合与 DSH | `engine.js`、`project-selector.js`、`host.js`：工作流选择及旧映射，复用 spawn、权限、工具、插件、存储和 UI |

## 内核事实

一次 Attempt 占用一次试验额度，可以包含多个 Invocation；每次调用记录 UUID、所属尝试、DSH 子会话、结束状态和错误。Artifact 保存制品类型、内容摘要、载荷、产生它的尝试及父制品。Observation 绑定制品与摘要、目标和评价版本、扩展 id/version 以及完整领域结果。Decision 引用实际观测，记录局部及全局选择和资格。

调用失败、制品是否完整、评价结果和是否保留是不同事实。领域结果不能覆盖核心身份；混用版本、血缘不一致或观测与结果不匹配时拒绝发布。工作流得到的 state/artifact 是副本，必须通过命令改变权威状态；扩展仍是受信任的 DSH 插件代码，接口不是安全沙箱。

## 方向与 Epoch

默认每轮额度 8 次尝试、20 分钟；每个 Epoch 最多 2 个方向，每方向最多 2 次局部尝试，串行执行。Advisor 一次返回整个 Epoch 的任务，执行前持久化；同一方向的局部尝试共用任务。新方向从该次规划时的全局最佳派生，已有方向沿用自己的局部最佳，未分配方向暂停但保留。

`direction` 是方法族，`lane` 是独立积累的候选分支；相同方向可有不同分支，省略 lane 时沿用 direction。已有分支不能偷偷换方法。设置中的方向数限制本次分配的分支数。

领域 `qualify` 区分可保留继续研究和可交付，默认二者都使用 `valid`。扩展可保留阶段结果，但 `valid:false` 不能交付。新分支第一个有变化且可保留的候选成为局部起点，即使落后全局；之后只保留局部改善。内置代码扩展仍要求修复与回归通过。

`incomparable` 不等于更差：非支配候选保存在 frontier，初始和评价升级都包含有资格的基线。界面展示多个保留候选，采用按钮仍针对全局最佳；当前没有从任意 frontier 候选手动交付的入口。

每次尝试记录目标版本、评价版本、Epoch、方向、父候选和实际评价。中断尝试保留为未完成，计入已用次数；恢复重用原计划，继续剩余局部尝试。评价升级使未完成的旧计划失效，下一次调用按新证据规划。

## 上下文重建

Advisor 的上下文从完整当前目标记录聚合：按方向给出结果计数、局部最佳，以及各类结果最早和最近两次的证据。原始历史不删除，不直接把全部 JSON 堆入提示词。Worker 只收到当前方向任务、保留候选、上次本方向反馈和冻结检查说明。

方向证据同时给出实际起点、父候选、执行者的改动报告、文件变化和失败阶段，`projectEvidence` 可补充领域摘要。文件检查失败时明确保留“变化情况未知”；报告不替代评价，历史记录缺少字段时不补造。

文件 Worker 未正常完成时，只有 DSH caller 已结算且 activation 与 owner 均释放，Host 才标记执行者停止。随后可核对的文件制品能够封存并独立评价；调用仍保持失败。执行者是否停止未知时不接纳文件，JSON 工作流需要明确返回完整制品。用户暂停、目标调整、额度耗尽或卸载立即停止新增执行，已封存制品保存为 pendingEvaluation；继续时先完成同一尝试的评价，不重复消耗试验额度。

代码工作流复制父候选前后核对封存身份，规划和评价副本也核对内容。保留目录被外部改动时阻止接续，不能静默改变下一代的起点。

同一 Epoch 的任务须能从各自起点独立执行，不能假设另一个方向尚未完成的输出已经可用。需要共同前置改动时，在一个方向内连续完成，或等待下一次规划使用已验证的候选。

假设与结果分开；未完成执行不能被当成方法无效。新评价的复验结论优先展示，同时保留历史状态，避免把已经证伪的旧成功再次当作有效证据。未复验的旧版本结果明确标记，不能跨版本混比分数。

主对话的控制工具只返回当前状态、实际已用额度、最佳候选、近期方向及最新审查摘要，不反复回传文件哈希和全部实验记录。完整历史仍由 Host 保存并在探索面板展示。

## 独立评价审查

代码工作流的任务扩展可提供 `review`，默认性能与缺陷修复都提供。首次评价建立后、候选准备采用前调用独立 Reviewer。它读取当前候选、原始参考和已有评价，只能在分配的补充检查目录新增文件；原有检查、源文件和参考项目都核对内容。自定义工作流通过 `reviseCriteria` 发起同样的完整评价升级，无需引入 Reviewer；默认 SLA 策略负责重排，内核核对全部候选的观测后发布。

补充检查返回独立 `passed/summary`，与原任务的 `valid` 分开。缺陷基线的目标复现可以使 `valid:false`，同时保留行为检查通过。审查方法必须保护目标修改范围之外的行为，不能把目标缺陷的旧错误输出固化为正确答案。没有具体检查时可报告未提出新检查，这不是覆盖所有行为的证明。

有新增检查时：

1. 保存待发布评价并立即撤销采用资格；目标版本不变，评价版本递增。
2. 在初始项目和本目标已有效且有改动的候选上执行同一套检查，逐项保存复验结果。原始项目必须通过补充检查，原任务基线仍由扩展验证。
3. 全部完成后一次发布新版评价、全局最佳与各方向局部最佳。旧 trial 的结果不改写，新结果另存为 assessment；失效方向回退到新版已确认候选或初始项目。
4. 中断恢复接着完成待发布事务。检查不适用或执行错误保留失败提案、撤销待发布状态；允许一次携带实际错误的重新审查，再失败则停下。不能以“没有新检查”抹掉先前失败。

初始通过、候选失败说明新增断言发现行为差异；断言是否表达正确需求仍依赖任务方法。界面显示原始审查意图、真实复验和失败原因，不宣称自动证明所有语义。

原评价和补充检查都在一次性副本中运行，前后核对完整非忽略项目内容和冻结评价文件。不能临时修复源文件或补一个缺失模块来取得通过；运行缓存使用原有忽略目录。原始输出保存在检查副本之外。

采用资格绑定目标版本、评价版本、任务扩展版本、候选编号与文件摘要。采用再次运行评价，写回时仍检查候选内容没有变化。扩展未提供 review 时沿用其原评价，记录为未提供审查；已经启动但失败或中断的审查不能绕过。

## 设置与升级

单次调用默认 24 个工作步、5 分钟，可通过已有 settings 的 `maxStepsPerCall`（4–200）和 `maxMinutesPerCall`（1–60）调整。旧探索缺少字段时沿用原 24 步、5 分钟。单次输出额度继承 DSH 当前会话的模型配置，不另设 Token 账本或覆盖模型限制。

工作步数之外另有 1 个只提交已有结果的步骤。最后一步通过 DSH 原生工具组装收起工作工具，并通过工具 guard 阻止继续执行；结构化角色只能提交原 schema，Worker 只能汇报已写入的改动和未验证事项。两阶段共用单次期限、整轮剩余时间和取消信号。未提交、schema 无效或超时仍按未完成处理；提交成功后仍须经过 Host 的独立评价。

通过主对话或右侧探索设置可指定每轮尝试数（1–100）、分钟（1–240）、方向数（1–4）及每方向局部次数（1–5）。运行中先暂停再配置；面板只提交改动字段，未编辑的额度保持不变。只修改方向数不改变剩余额度，已持久化的 Epoch 计划保持原次数，新配置用于下一 Epoch。预算字段按本轮起点重新计算，不抹掉已用量。明确继续会在额度用完或本轮结束后授予新的有限额度。只检查候选不新增 Worker 实验。

存储格式升级到 4；旧记录仍可查看，不补造方向、Epoch 或观测。继续格式 3 的文件探索时，先核对 manifest，按原依据独立重测基线与保留候选，发布新评价版本，再恢复搜索。旧 pendingReview 的部分测量另存 legacyEvaluations，成功迁移后仍可追溯。内容身份缺失、内容改变或原扩展版本缺失时停止接续并说明原因。旧 registerTask API 保留，内置代码任务版本仍为 `1.1.0`；已采用文件不受影响。

自定义交付回调在副作用前调用 authorize，返回持久回执。失败原因先保存，再核对 `delivered`（已交付并返回回执）、`absent`（确认无副作用，可重试）、`unknown`（继续阻止采用）。进程恢复使用同一接口，不把没有证据当作没有副作用。代码工作流继续使用原有文件写回与回滚日志，参数工作流交付包含制品身份与评价版本的 JSON 包。

这版没有并行 Worker、远程候选快照或独立 Token 账本。用量仍看 DSH；Windows 文件策略仍不提供读隔离或网络隔离。恢复与协议验收证明这些状态规则，不能据此推断长程搜索收益。
