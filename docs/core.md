# 0.3 探索核心

一个目标可以发展多个方向。每个方向保留自己的有效候选，Advisor 根据各方向的实际证据规划下一轮，Worker 每次从本方向的候选继续。所有模型调用仍使用 DSH 新会话；候选、计划与结果由 Host 保存。

## 方向与 Epoch

默认每轮额度 8 次尝试、20 分钟；每个 Epoch 最多 2 个方向，每方向最多 2 次局部尝试，串行执行。Advisor 一次返回整个 Epoch 的任务，执行前持久化；同一方向的局部尝试共用任务。新方向从该次规划时的全局最佳派生，已有方向沿用自己的局部最佳，未分配方向暂停但保留。

新方向的第一个有效且有改动的候选成为局部基线，即使落后全局最佳；之后只保留该方向的改善。全局最佳独立比较。无效、未完成评价和无改动候选均不能替换局部最佳。缺陷扩展的有效性仍要求修复与回归通过，所以这版不把“修了一半”当作有效局部成果。

每次尝试记录目标版本、评价版本、Epoch、方向、父候选和实际评价。中断尝试保留为未完成，计入已用次数；恢复重用原计划，继续剩余局部尝试。评价升级使未完成的旧计划失效，下一次调用按新证据规划。

## 上下文重建

Advisor 的上下文从完整当前目标记录聚合：按方向给出结果计数、局部最佳，以及各类结果最早和最近两次的证据。原始历史不删除，不直接把全部 JSON 堆入提示词。Worker 只收到当前方向任务、保留候选、上次本方向反馈和冻结检查说明。

假设与结果分开；未完成执行不能被当成方法无效。新评价的复验结论优先展示，同时保留历史状态，避免把已经证伪的旧成功再次当作有效证据。未复验的旧版本结果明确标记，不能跨版本混比分数。

主对话的控制工具只返回当前状态、实际已用额度、最佳候选、近期方向及最新审查摘要，不反复回传文件哈希和全部实验记录。完整历史仍由 Host 保存并在探索面板展示。

## 独立评价审查

任务扩展可提供 `review`，默认代码性能与缺陷修复都提供。首次评价建立后、候选准备采用前调用独立 Reviewer。它读取当前候选、原始参考和已有评价，只能在分配的补充检查目录新增文件；原有检查、源文件和参考项目都核对内容。

补充检查返回独立 `passed/summary`，与原任务的 `valid` 分开。缺陷基线的目标复现可以使 `valid:false`，同时保留行为检查通过。审查方法必须保护目标修改范围之外的行为，不能把目标缺陷的旧错误输出固化为正确答案。没有具体检查时可报告未提出新检查，这不是覆盖所有行为的证明。

有新增检查时：

1. 保存待发布评价并立即撤销采用资格；目标版本不变，评价版本递增。
2. 在初始项目和本目标已有效且有改动的候选上执行同一套检查，逐项保存复验结果。原始项目必须通过补充检查，原任务基线仍由扩展验证。
3. 全部完成后一次发布新版评价、全局最佳与各方向局部最佳。旧 trial 的结果不改写，新结果另存为 assessment；失效方向回退到新版已确认候选或初始项目。
4. 中断恢复接着完成待发布事务。检查不适用或执行错误保留失败提案、撤销待发布状态；允许一次携带实际错误的重新审查，再失败则停下。不能以“没有新检查”抹掉先前失败。

初始通过、候选失败说明新增断言发现行为差异；断言是否表达正确需求仍依赖任务方法。界面显示原始审查意图、真实复验和失败原因，不宣称自动证明所有语义。

原评价和补充检查都在一次性副本中运行，前后核对完整非忽略项目内容和冻结评价文件。不能临时修复源文件或补一个缺失模块来取得通过；运行缓存使用原有忽略目录。原始输出保存在检查副本之外。

采用资格绑定目标版本、评价版本、任务扩展版本、候选编号与文件摘要。采用再次运行评价，写回时仍检查候选内容没有变化。扩展未提供 review 时沿用其原评价，记录为未提供审查；已经启动但失败或中断的审查不能绕过。

## 设置与升级

单次调用保留 24 个工作步，另有 1 个只提交已有结果的步骤。最后一步通过 DSH 原生工具组装收起工作工具，并通过工具 guard 阻止继续执行；结构化角色只能提交原 schema，Worker 只能汇报已写入的改动和未验证事项。两阶段共用原 5 分钟期限和取消信号。未提交、schema 无效或超时仍按未完成处理；提交成功后仍须经过 Host 的独立评价。

通过主对话可指定每轮尝试数（1–100）、分钟（1–240）、方向数（1–4）及每方向局部次数（1–5）。运行中先暂停再配置；只修改方向数不改变剩余额度，已持久化的 Epoch 计划保持原次数，新配置用于下一 Epoch。预算字段按本轮起点重新计算，不抹掉已用量。明确继续会在额度用完或本轮结束后授予新的有限额度。只检查候选不新增 Worker 实验。

存储格式升级到 3；历史 trial 不补造方向或 Epoch。默认任务扩展升到 `1.1.0`，保留旧 `1.0.0` 绑定。旧运行可以查看，继续或采用需要原版本扩展；新规则请新建会话。已采用文件不受影响。

这版没有并行 Worker、远程候选快照或独立 Token 账本。用量仍看 DSH；Windows 文件策略仍不提供读隔离或网络隔离。恢复与协议验收证明这些状态规则，不能据此推断长程搜索收益。
