## 发现与处理

| 发现 | 影响及证据 | 已实现的处理 |
| --- | --- | --- |
| 高级字段无效，折叠后保存没有可见反馈 | 实际输入小于允许范围的步数，收起高级设置后提交；用户不知道保存失败在哪里 | 与服务端共用 schema；字段旁显示范围和错误；保存自动展开并聚焦首个错误；无效值不发送 |
| 采用入口位于候选差异和检查之前 | 用户先碰到提交操作，必须继续向下寻找依据 | 对比结果、查看内容、检查结果依次位于采用按钮之前 |
| 保存过程、未保存草稿不明确 | 延迟/失败请求下难以判断操作是否完成 | 展示正在保存、未保存、成功和具体失败；失败保留草稿，支持撤销修改 |
| 交付回执直接展示 JSON | 文件路径混在转义字符和制品元数据中 | 有路径的回执直接显示结果文件、复制路径；原始回执折叠保留；未知格式仍可查看 |
| 暗色主题的通过文字对比度不足 | 实际计算样式 `rgb(35,131,83)` 对 `rgb(21,21,23)`，约 3.86:1 | 改用宿主成功色与主文字色混合，并保留文字状态；复核明暗主题计算样式 |
| 结果页说明多而信息少 | 重复候选身份、泛泛的选择解释及范围声明没有提供可操作事实 | 删除这些说明；真实数据、真实改动说明、具体未验证事项继续展示 |

## 小字是否必要

判断标准：这句话是否提供当前控件和结果中没有的信息，并且会改变用户的操作或判断。只有“帮助理解”“更安心”这类理由不能支持保留。下表的依据来自实现和复现；未进行用户实验，不声称已经测得完成率提升。

| 原文或内容 | 处理 | 具体依据 |
| --- | --- | --- |
| “候选实测 · 候选 #… · 评价版本 …” | 删除 | 候选号已在标题，测量身份已在对比行，评价版本在判断依据中。重复没有增加区别信息 |
| “候选内容已封存，可展开查看实际变化” | 删除 | 没有说明改了什么；下方“查看候选内容”已经是实际入口 |
| “为什么保留／按当前评价规则保留候选 #…” | 删除 | 复述“保留”，没有回答原因；改由初始/候选实测与检查证据供判断 |
| “结论覆盖当前评价数据和规则，完整范围见判断依据”等泛化范围声明 | 删除 | 未指出任何具体数据范围或未测行为。明确的评价内容仍可展开阅读 |
| 未提供结构化说明、未提供未验证事项的占位解释 | 删除 | 这是数据缺项的实现信息；空标题不能帮助判断候选。仅在存在实际内容时展示对应区域 |
| “未提供行为名称” | 删除 | 无标题的检查已有“补充检查 N”作为标识；重复解释缺少标题不会帮助理解检查结果 |
| 底部重复的整轮额度、步数和“尚未写回” | 删除 | 页首已有尝试状态，设置中已有额度；重复占用垂直空间 |
| 设置中的 Token 用量说明 | 从表单删除 | 该表单不操作 Token；使用说明已交代 DSH 用量入口 |
| “继续探索以尝试其他方向……” | 删除 | 重复按钮含义，没有补充条件或结果 |
| “补充要求”提示 | 改短为“补充要求：在主对话发送。” | 面板没有补充要求输入框；提示给出实际入口，`steer` 会保存要求并重建评价依据 |
| “已交付结果，候选与评价依据已保留” | 改短为“结果已交付。” | 需要明确交付状态；评价保留已由下方可访问内容体现 |
| 输入范围，如“整数范围：4–200” | 保留，13px | `settingsSchema` 实际拒绝越界和小数；只看“单次工作步数”无法知道范围。错误状态直接替换为“请输入整数：4–200” |
| “调整额度会保留已用次数和时间，不会重新开始探索” | 保留于设置内，13px | `configure` 以本轮起点计算上限，不重置已用量；删除会留下“改额度是否重新开始”的操作歧义 |
| 单次额外 1 步、整轮剩余时间、下一次规划生效 | 保留于高级设置内，13px | Host 为提交预留 1 步；调用时间受整轮剩余额度约束；已建立的规划不会因修改方向数立即替换 |
| 采用前复验及写回/交付说明 | 缩短并保留于按钮前 | 代码采用会写入项目，参数采用会重新评价并交付；单独“采用”不能说明操作效果。项目变动会使代码采用停止 |
| 历史检查来源提示 | 保留于展开的来源记录内 | 历史审查可能指出失败，而当前复验已通过。提示区分两次观测，防止把历史问题当作当前结果 |
| “执行者的改动说明”、具体“尚未验证”内容 | 有实际内容才保留 | 区分执行者陈述与评价结果；具体未测行为会影响采用决定，不用泛化免责文案填空 |
| “初始项目／制品 → 当前候选” | 保留于展开的差异中，13px | 明确差异的比较基点；候选也有父候选，不能默认每个 diff 都是上一候选到当前候选 |
| 同步失败、正在处理、未保存、保存失败、复制成功/失败 | 按实际状态显示 | 分别说明缓存是否最新、请求是否完成、草稿是否持久化和结果如何取回；不是常驻装饰文字 |
| 二进制/大文件无法预览、候选已更新需重试 | 条件显示 | 这些是当前预览的真实限制，并给出证据目录或重试操作 |
| 保留候选中“不可比结果共同保留” | 仅有多个候选时显示 | 多目标评价允许不可比结果；解释为何没有单一排序结果，而非虚构“最佳分数” |

文字层级也随之调整：必要的说明、路径、范围和字段错误使用 13px；时间、状态标签等短元数据保留 12px。标签、数值、版本号属于识别信息，不通过增加说明段落解释。

## 参考怎样改变设计

选择两套直接匹配本次问题的官方模式，另用一项技术准则检验文字可读性。

| 官方来源 | 借鉴的具体细节 | 在本插件中的变化 |
| --- | --- | --- |
| [Carbon Number input](https://www.carbondesignsystem.com/building-blocks/core/components/number-input/guidelines) | 持续可见的标签、范围辅助信息、字段级错误、40px 输入尺寸 | schema 范围、行内错误、关联描述、40px 输入高度；隐藏错误自动展开并聚焦是本产品针对已复现问题的补充 |
| [GOV.UK Summary list](https://design-system.service.gov.uk/components/summary-list/) 与 [Check answers](https://design-system.service.gov.uk/patterns/check-answers/) | 用键值行概括已知信息；提交之前允许检查内容 | 基线/候选两行对比；把改动和检查放到采用之前；交付文件替代默认大段 JSON |
| [WCAG 2.2 Contrast minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) | 普通文字至少 4.5:1，以前景与背景计算 | 修复实际暗色“通过”文字的对比度；不把截图看起来清楚当作通过依据 |

没有照搬参考站点的视觉皮肤，也没有给未知总量的探索添加百分比进度。
